# Pharos REST API (v1)

Pharos exposes a versioned REST API under `/api/v1`. It is the same API the
Expo mobile app uses, and it is stable enough to build your own
clients or scripts against. Every route runs on the Node.js runtime and talks to
the same MongoDB as the web app, so anything you change through the API shows up
in the web UI (and vice versa).

- Base URL: `http://<your-pharos-host>:3000/api/v1` (or your reverse-proxied
  HTTPS domain, e.g. `https://pharos.example.com/api/v1`).
- Content type: `application/json` for request/response bodies, except the file
  upload endpoints, which take `multipart/form-data`.
- Auth: bearer token on every route except `POST /auth/login` (see below).

> This reference is generated by reading the route files under
> `apps/web/src/app/api/v1/`. It is the source of truth for the mobile client; if
> a shape here disagrees with the code, the code wins, so please open an issue.

## Authentication

Pharos is multi-user. Each user has a personal **API token** (a string that
begins with `phk_`). Send it as a bearer token on every request:

```
Authorization: Bearer phk_xxxxxxxxxxxxxxxxxxxxxxxx
```

### Get a token

**`POST /api/v1/auth/login`** — the only unauthenticated endpoint.

Request:

```json
{ "username": "achilleas", "password": "••••••••" }
```

Response `200`:

```json
{
  "token": "phk_xxxxxxxxxxxxxxxxxxxxxxxx",
  "user": { "id": "665...", "name": "Achilleas", "username": "achilleas", "role": "admin" }
}
```

The token is the user's `apiToken`. It is created on first login and stays
stable afterward, so a client can store it and reuse it. You can also copy it
from the web app under **Settings** (Mobile/MCP access). `role` is `admin` or
`member`; a few destructive endpoints require `admin` (noted below).

Errors: `400` (missing/invalid body), `401` (bad credentials).

### Using the token

Every other endpoint is wrapped with a shared auth guard. Without a valid token
you get:

```json
{ "error": "Unauthorized — send Authorization: Bearer <token>" }
```

with status `401`. A thrown server error returns `500` with the same
`{ "error": "..." }` shape.

## Conventions

### List envelope and pagination

All list (`GET`) endpoints return a uniform envelope:

```json
{ "data": [ ... ], "total": 128, "limit": 50, "offset": 0 }
```

Query params supported by list endpoints:

| Param          | Default | Meaning                                                        |
|----------------|---------|----------------------------------------------------------------|
| `limit`        | `50`    | Page size, clamped to `1..200`.                                |
| `offset`       | `0`     | Number of records to skip.                                     |
| `updatedSince` | —       | ISO date; returns only records with `updatedAt >= it`.         |

### Incremental sync

When `updatedSince` is set, list endpoints **also** include soft-deleted
records, each flagged `"deleted": true`. This lets a client doing incremental
sync (poll with the timestamp of its last fetch) learn about both changes and
deletions in one call, then drop the deleted ones locally.

### Soft delete

`DELETE` on Items, Receipts, Expenses/Income, Subscriptions, Vouchers, and Tasks
is a **soft delete**: the record moves to Trash and is recoverable. Cards and
Stores are deleted permanently (they are not soft-deleted). See the
[Trash](#trash) endpoints to list, restore, or purge.

### IDs and errors

- Record IDs are 24-character hex Mongo ObjectIds. Malformed IDs return `400`.
- Errors are always `{ "error": "<message>" }` with an appropriate status
  (`400` bad input, `401` unauthorized, `403` forbidden, `404` not found,
  `500` server error).

### AI-backed endpoints

Some endpoints call the configured AI provider (Anthropic/Ollama/etc.) and are
gated behind a per-feature toggle in Settings. If the relevant feature is off or
the provider is misconfigured, they return a friendly error instead of acting.
These are flagged **(AI)** below with the feature name.

## Endpoints

### Dashboard & reports

| Method | Path            | Description |
|--------|-----------------|-------------|
| GET    | `/overview`     | Headline counts (items, shopping list, receipts, expenses, subscriptions, open tasks) + installments owed, active plan count, currency. For a mobile dashboard. |
| GET    | `/reports`      | Money summary: net position, this month/year, by-category, last 6 months. |
| GET    | `/calendar`     | 3-month money agenda: subscription renewals (stepped per cycle), card installments aggregated per month, projected recurring bills/income, warranty + voucher expiries, per-month in/out totals. Also a flat `events` array for backward compatibility. |
| GET    | `/search?q=`    | Global search across all data → `{ hits: [{ type, id, title, subtitle }] }`. |

### Items (inventory & shopping)

| Method | Path                              | Description |
|--------|-----------------------------------|-------------|
| GET    | `/items?status=shopping\|inventory\|all` | List items (+ `limit`/`offset`/`updatedSince`). |
| POST   | `/items`                          | Create. Body `{ title, status?, category?, currentPrice? }` → `{ item }`. |
| GET    | `/items/:id`                      | Full detail (links, price history, photos, warranty, purchase) + a computed `price` block (best-now, lowest/highest, trend, verdict, where-to-buy) for the mobile price panel. |
| PATCH  | `/items/:id`                      | Update `{ title?, status?, category?, currentPrice?, targetPrice?, specs?, tags? }`. |
| DELETE | `/items/:id`                      | Soft-delete. |
| POST   | `/items/import`                   | **(AI: itemsImport)** Fetch a product page, AI-parse, add or merge. Body `{ url, view? }` (`view` = `shopping` default \| `inventory`) → `{ ok, id, title, price, store, updated }`. |
| POST   | `/items/:id/ai-fill`              | **(AI: itemsImport)** Fill specs/category/tags from the item's links or web search. Body `{ mode: 'specs' \| 'info' }`. |
| POST   | `/items/:id/price`                | Log an observed price. Body `{ price, store? }` (appends to priceHistory, updates currentPrice). |
| POST   | `/items/:id/convert-to-task`      | Create a Task seeded from this item (title, price, links, tag `shopping`); the item is untouched. |
| GET    | `/items/:id/plans`                | Installment plans across all statements, each flagged `linked` for this item. Linked first, then active, then by soonest payoff. |
| POST   | `/items/:id/link-plan`            | Attach this item to a plan (additive). Body `{ signature }`. |
| DELETE | `/items/:id/link-plan`            | Detach this item from a plan, keeping other products. Body `{ signature }`. |

| DELETE | `/shopping-list/:id`      | Remove. |

### Receipts

| GET    | `/receipts?store=&archived=1`     | List receipts (+ `limit`/`offset`/`updatedSince`). |

### Scan (AI capture, mostly no-save)

| Method | Path                | Description |
|--------|---------------------|-------------|
| POST   | `/scan/receipt`     | **(AI)** `multipart` field `file` (image/PDF). Saves the file, parses, creates the receipt → `201 { receipt: { …, lineItems, aiUsed, aiError } }`. This one **persists**. |
| POST   | `/scan/product`     | **(AI)** `multipart` field `file` (product image) → `{ data: { name, brand, category, quantity, notes } }`. No save. |

| POST   | `/scan/voucher`     | **(AI: vouchers)** JSON `{ text }` or `multipart` `file` → `{ data: { title, code, store, discount, expiresAt, url, notes } }`. No save. |

## Quick start

```bash
BASE="http://localhost:3000/api/v1"

# 1. Log in and capture the token
TOKEN=$(curl -s "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"achilleas","password":"YOUR_PASSWORD"}' \
  | python3 -c 'import sys,json; print(json.load(sys.stdin)["token"])')

# 2. Use it on any endpoint
curl -s "$BASE/overview" -H "Authorization: Bearer $TOKEN"

# 3. Create a task
curl -s "$BASE/tasks" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Order SFP28 cable","tags":["network"]}'

# 4. Incremental sync (only records changed since a timestamp)
curl -s "$BASE/items?updatedSince=2026-07-01T00:00:00Z&limit=200" \
  -H "Authorization: Bearer $TOKEN"
```
